Pratidaan (Drop assistant)

Reviewer guide. Not linked from the live app UI — for people evaluating the prototype.

Voluntary blood donor app for India: impact tracing, donation health panel, illustrative health-linked cover, and AI assistant Drop. Deployed on Azure App Service (Linux F1) with Azure OpenAI (gpt-5-mini).

Guardrails (three layers)

Implemented in backend/src/ai/guardrails.js. Every Azure OpenAI call can append the same safety block via llm.js (guardrailKind).

1. Before the model (Drop chat only)

Regex on the donor’s message: block diagnosis/prescription asks and emergency wording with a fixed reply (often + check-up card). The LLM is not called when blocked.

2. In every system prompt

augmentSystem() appends shared rules: Pratidaan scope only, refuse essays/homework, no diagnose/prescribe, emergencies → call emergency services, facts from tools only.

3. After the model

sanitizeReply() strips prescription-like wording. Structured JSON is schema-validated; Card rewrites must match rule text.

  • Rule-based fallback() when Azure OpenAI is unavailable or the reply is incomplete.
  • Chip questions (donate, BP, impact, …) can bypass the full agent for deterministic answers.
  • Tests: backend/test/guardrails.test.js, ai-correctness.test.js.

Known limits

  • Blood centre / clinic slots are not real reservations; Calendar events may be created but do not confirm a centre.
  • Cover and premiums are an illustrative model, not issued insurance.
  • AI safeguards (production bicep defaults): ~30k tokens/day and 100 calls/day per instance, 2 req/s; App Service F1 is single-instance shared CPU.
  • Signed-in account JSON and chat cycles persist in Azure Blob Storage (managed identity). Guests use in-memory state unless Blob mirrors chat.
  • Agent blobs (agents/sessions/*, chat-cycles/*) mirror activity; replies still come from runAgent() on Azure OpenAI. See docs/AGENT_PLATFORM_SETUP.md.
